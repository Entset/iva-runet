# 04. Слежение за ценой (WATCH)

## Инструменты по площадке

| Площадка | Как снимаем цену | Почему |
|---|---|---|
| Маркет | MCP `yandex_search` / `yandex_card` | коннектор marketplace работает с сервера (2026-10-26); браузер не нужен |
| WB | браузером через ruweb (`market-order.sh search wb`) | MCP wb_* = 403 с сервера (2026-10-26) |

## Запись WATCH

`~/.config/market-order/watch-<slug>.json`: `{url, target_price, last_price,
threshold_pct, delta_rub, channel, updated}`. `<slug>` — id товара/артикул.

Создание — по просьбе владельца («следи за ценой X, скажи если ниже N»): запиши
цель (target_price) или порог (threshold_pct), возьми текущую цену как last_price.

## Проверка по cron

- Раз в `WATCH_INTERVAL_H` (конфиг, по умолчанию 6 ч): schedule с командой
  `market-order.sh stage market --mcp up` (или WB `stage wb`) — стадия до браузера;
  затем снять цену, сравнить.
- **Тишина, если цена не изменилась.** Пишем владельцу ТОЛЬКО когда:
  1. цена ≤ target_price (цель достигнута);
  2. цена упала/выросла не меньше чем на `WATCH_DELTA_RUB` (конфиг, ₽) или на
     `WATCH_THRESHOLD_PCT` (% от прошлой);
  3. товар пропал из наличия (in_stock=false / кнопки корзины нет).
- После записи обновляй last_price в watch-файле — иначе один спам.

## Порядок одного прохода

1. Стадия (BLOCK/NO_MCP — пропуск прохода без шума; послеcooldown просто ждать).
2. Цена: MCP для Маркета; WB — `search wb`/открыть карточку ruweb-темпом.
3. Сравнить с watch-файлом; правило тишины выше.
4. Записать last_price, updated.

## Экономика и аккуратность

- Слежение без браузера, где можно (04-monitor и 01-preflight): не гонять ruweb ради
  «просто посмотреть».
- Цены для владельца называем только регулярную цену покупки; «с картой/подпиской»
  (Пэй/Plus, WB-кошелёк) — упоминать отдельно как условие, не как цену.
